# 安全说明

[← 返回 README](../README.md) · [文档目录](README.md)


- 所有工具均为**只读**，agent 不会修改你的日志或源码。
- git 工具只执行 `log` / `show` / `blame` / `cat-file` / `rev-parse`，只读对象库、不读工作区：关闭分页器、外部 diff、textconv、
  fsmonitor、签名校验与交互提示，避免不可信仓库通过配置（fsmonitor、clean 过滤器、`gpg.program` 等）执行命令；
  `path` 参数不能越出 `-c` 指定的目录，大 diff 流式读取、到上限即停止。
- 工具只能访问本次排查登记的日志（`-l` 或会话里添加的）和源码目录（`-c`）及其子目录；模型传入其它路径
  （比如被日志里的提示注入诱导去读 `/etc/passwd`、`~/.ssh`）会直接返回"拒绝访问"。系统提示也要求模型把日志、
  源码、提交说明当作数据而不是指令。评测集里的 `prompt-injection` 案例专门回归这一点。
- 同一轮里参数完全相同的重复工具调用不会再执行，直接提示模型换关键词或区间；搜索类工具的返回条数有硬上限，
  模型传入过大的 `max_results` 会被截到上限。
- 私钥块按整份文件定位后逐行遮盖（保持行号），只读取 / blame 私钥中间几行或 diff 被截断时也不会漏出正文。
- 日志/源码内容会发送给模型服务。工具输出默认先脱敏：日志中的 token / 密码 / 手机号 / 身份证（带校验位校验，
  不会误伤订单号）/ 邮箱 / IP（同一 IP 映射为同一代号，仍能区分机器）会被打码；源码只打明确的密钥
  （`sk-`、AccessKey、JWT、Bearer、连接串里的密码）和凭据键名后的字面量（`.env` 的 `DB_PASSWORD=xxx`、
  `api_key = "xxx"`），`password = os.environ[...]`、`${TOKEN}` 这类引用不改动。规则无法覆盖所有业务字段，高敏数据建议改用本地模型。
- Web 界面（`log-agent serve`）默认只监听本机并要求访问令牌；分享链接只读、可过期可撤销、库里只存哈希，
  只能读取该会话登记过的日志与源码目录，内容始终脱敏。详见 [Web 界面](web.md#访问控制与安全)。
- 网页「设置」保存的 API Key 写在 `~/.log-agent/credentials.toml`，权限 0600、原子写入，和可能被复制或提交的 `config.toml` 分开存放；
  接口只返回 `sk-…abcd` 这样的掩码，从不回传完整 Key。设置接口只对本人开放，修改要求访问令牌和防跨站请求头，分享链接无法访问。
